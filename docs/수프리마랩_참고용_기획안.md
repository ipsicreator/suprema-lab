## 1. 서비스의 목적

수프리마랩은 학원의 담당 컨설턴트가 학생부와 성적을 분석하고, 탐구·독서·세특 코칭과 입시 위치 진단을 연결하여 상담·보고서 업무를 수행하는 서비스다. 본사는 공통 입시 근거와 운영 정책을 관리하고, 학원은 소속 담당자와 학생의 업무를 관리하는 구조를 목표로 한다.

입결 엑셀을 개발자가 매번 코드에 넣는 방식에서 벗어나, 권한 있는 관리자가 직접 파일을 올리고 검증한 뒤 반영·복원할 수 있게 한다. 진단 결과는 실제 입력과 비교 근거로 설명하며, 근거가 부족하면 판단을 보류한다.

**개발 판단은 기존 프로젝트를 개선하여 유지하는 것이다.** 화면·진단·자료 처리·배포 기반을 재사용하고, 학원별 권한·학생 배정·영구 저장은 추가로 설계·구현한다. 전체 폐기와 전면 재개발은 현재 채택하지 않는다.

## 3. 운영 구조와 용어

**마스터 → 본사 관리자 → 학원(학원 관리자) → 담당 컨설턴트 → 배정 학생**

학원은 조직이며 역할 이름이 아니다. ‘학원 관리자’는 해당 학원을 운영하는 계정 역할이다. 실제 상담·분석을 수행하는 사람은 **담당 컨설턴트**로 부른다. 기존 ‘멘토’ 표현은 별도의 권한 역할로 사용하지 않는다. 한 사람이 학원 관리자와 담당 컨설턴트를 겸할 수 있다.

| 구분 | 관리 범위 | 목표 업무 |
|---|---|---|
| 마스터 | 플랫폼 전체 | 본사 관리자 지정, 권한·가격 정책, 공통 근거와 판단 기준 승인 |
| 본사 관리자 | 배정 학원 | 학원 등록·운영 지원, 계약·이용권·사용량 관리 |
| 학원 관리자 | 소속 학원 | 담당자 초대·해제, 학생 등록·담당 배정, 결과 검토 |
| 담당 컨설턴트 | 배정 학생 | 자료 확인, 진단·탐구·상담, 보고서 작성·검토 |
| 학생·학부모 | 본인에게 공개된 결과 | 결과 열람·수신을 우선 검토. 직접 실행 기능은 후속 범위 |

학원명·학교명·이름 입력만으로 권한을 부여하지 않는다. 학생이 재학하는 학교와 서비스를 이용하는 학원을 구분한다. 학원 소속과 담당 배정은 서버와 저장소에서 확인해야 한다. 현재 화면의 담당자 이름 표시는 계정 권한이나 실제 배정 구현을 대신하지 않는다.

## 4. 전체 화면과 이용 흐름

현재 확인한 화면은 루트의 소개 화면 이동을 제외한 25개 경로다. 같은 주소에서 입력·대기·결과로 바뀌는 상태는 별도로 설명하며, 각 상태를 모두 실행 완료한 것으로 보지 않는다.

### 흐름 A. 서비스 소개와 자료 검색

소개 → 학생 진단 진입 또는 입시 자료 검색.

| 화면 | 경로 | 주요 구성 |
|---|---|---|
| 서비스 소개 | /intro | 브랜드·서비스 설명, 4단계 진입, 자료 검색·보고서 연결 |
| 입시 검색·시뮬레이션 | /diagnosis | 입시 위치 검색과 입학전략 시뮬레이션 탭 |
| 홍보 안내 | /leaflet | 진단·세특 서비스 소개, 외부 채널 |

루트 주소 `/`는 `/intro`로 이동한다. 홍보 안내는 별도 소개 기능으로 보존되어 있다.

### 흐름 B. 학생별 주요 진단

정보·학생부 → 분석 → 탐구·독서·세특 → 입시 위치 → 보고서.

| 순서 | 화면·경로 | 입력·표시 | 다음 업무 |
|---|---|---|---|
| 1 | 정보·학생부 /diagnosis/step1 | 학생·학교·학년·담당자·진로·성적 체계, 학생부 자료 | 추출 내용 확인 후 분석 |
| 2 | 학생부 분석 /diagnosis/step2 | 실제 입력 성적과 학생부 정보, 표·그래프·분석 내용 | 보완점과 탐구 방향 검토 |
| 3 | 탐구·독서·세특 /diagnosis/step3 | 관심 과목·키워드, 기본·추가 주제, 탐구 방향·자료·문장 | 검토한 주제를 입시 진단에 연결 |
| 4 | 입시 위치 /diagnosis/step4 | 대학→모집단위→전형유형→전형명, 결과·근거 | 진단 완료 후 보고서 |
| 5 | 보고서 /report | 실제 완료한 진단 결과, 입력 요약·판정·근거 | 검토·인쇄·전달 |

현재 단계별 작업은 브라우저 저장값을 활용한다. 계정에 연결된 학생별 작업함, 여러 기기에서의 재개, 상담·확정·공개 이력은 후속 개발 대상이다. 결과 화면이 있는 것과 조직별 영구 보관 체계가 있는 것은 구분한다.

### 흐름 C. 별도 탐구·세특 기능

| 화면·경로 | 흐름 | 정리 방향 |
|---|---|---|
| 상세 평가 /diagnosis/step1/evaluation | 학생부 상세 확인 → 탐구 추천 | 주요 진단의 분석 단계와 관계 정리 |
| 탐구 추천 /exploration | 관심·진로 → 추천 주제·대학 가이드 → 솔루션 | 학생별 작업에 연결 |
| AI 솔루션 /solution | 키워드·학생부·학과 → 생성 → 탐구·독서·세특 결과 | 생성 결과 검토·수정·저장 체계 보완 |
| 별도 세특 /setuk | 학생 정보 → 탐구 활동 → 생성 대기 → 문장 | 주요 흐름의 세특 기능과 중복 진입 정리 |

기존 기능을 즉시 폐기하지 않는다. 학생별 공통 정보와 결과 저장을 먼저 통합한 뒤 중복 메뉴를 줄이는 것이 적절하다.

### 흐름 D. 입시DNA프리즘

소개 → 기본정보·약식 24문항 → 약식 결과 → 추가 24문항 → 병목 리포트 → 실행 가이드.

현재 독립된 진단 기능이다. 향후 학생 소속·담당 배정·상담 기록과 연결한다. 화면의 설명 문구와 검사 결과만으로 별도의 효과 검증이 이루어졌다고 표현하지 않는다.

## 5. 이번에 반영한 화면 편의성 개선

- 이미지로 표시하던 공통 진단 제목·설명을 일반 글자로 변경하여 잘림과 큰 여백 개선.
- 진단 상단에 저장된 학생·학교·학년·담당자 표시와 정보 확인·수정 경로 추가.
- 현재 단계 표시, 이전 단계 이동, 입시 자료 검색·홈 이동 제공.
- 탐구·독서·세특 화면을 공통 진단 흐름에 포함하고 이전·다음 이동 추가.
- 1024px 최소 가로폭 강제를 해제하고 모바일 단계·정보 영역을 재배치.
- 소개 화면 표시 명칭과 브라우저 제목을 수프리마랩으로 정리.

앞으로는 학생 선택을 업무 시작점으로 두고, 진행 상태·작성자·근거 버전·검토 상태를 화면에 함께 표시한다. 역할별 개선 시안은 검토자료이며 실제 학원 관리 기능으로 구현된 상태는 아니다.

## 6. 입결 원본과 7.24 자료의 위치

원본은 프로젝트 밖의 바탕화면 `수시` 폴더에 보존되어 있다.

`2027학년도 수시전형 및 입결 검색기_대치수프리마_V7.24.xlsx`

- 검증한 시트: 전체
- 실제 열 제목: 3행
- 유효 전형: 26,410개 / 대학: 164개
- 파일명에 있는 2027학년도와 파일 안의 2026학년도 입결 항목은 구분한다.
- 원본 엑셀을 수정하거나 운영 서비스에 자동 게시하지 않았다.
- 전체 파일 업로드·진단 검증은 별도 임시 저장소에서 실행했다.

‘원본 엑셀이 없다’와 ‘서비스에 활성화된 입결이 없다’는 서로 다르다. 이번 배포 후 운영 조회는 0행으로 확인했다. 실사용 전에는 저장소 설정을 확인하고, 관리자가 해당 파일을 검증·반영해야 한다. 기존 번들에는 초기 조사에서 빈 레코드 26,411개가 있었으며 이를 실제 입결 자료로 취급하지 않는다.

## 7. 관리자의 파일 반영 방법

파일 선택 → 시트 선택 → 검증·미리보기 → 전체 교체 확인 → 서비스 반영 → 필요 시 이전 버전 복원.

| 항목 | 현재 구현 기준 |
|---|---|
| 파일 형식 | XLSX·XLS·CSV·TSV |
| 원본 한도 | 20MB |
| 행 한도 | 최대 50,000개 |
| 전송 | 브라우저에서 해석 후 압축한 행 자료, 최대 3MB |
| 필수 열 | 대학·모집단위·전형유형·전형명 |
| 제목 탐색 | 첫 30행에서 실제 열 제목 확인 |
| 반영 단위 | 선택한 한 시트가 공통 자료 전체를 교체. 여러 파일 추가 병합은 미지원 |
| 임시 저장 | 미리보기만으로 서비스 자료를 바꾸지 않음 |
| 복원 | 보존된 버전 중 최근 반영 이력을 이용 |

반영 후 새로 열거나 새로고침한 입시 검색·시뮬레이션·진단은 같은 활성 자료를 사용한다. 자료 교체 때문에 앱을 다시 배포할 필요는 없다. Vercel에서는 임시 파일시스템에 영구 저장하지 않으며, PocketBase 설정이 없으면 반영·복원을 차단한다.

자세한 절차: [관리자 입시 데이터 업로드](관리자_입시데이터_업로드.md)

## 8. 진단과 판단 근거의 원칙

- 대학·캠퍼스·모집단위·전형유형·전형명이 맞는 자료를 비교한다.
- 평균, 50%컷, 70%컷, 등급, 환산점수를 혼합하지 않는다.
- 빈 값·오류·복합 값·중복 충돌은 임의 수치로 채우지 않는다.
- 비교할 근거가 없으면 ‘적정’으로 판정하지 않고 ‘판단 보류’로 표시한다.
- 2026·2025·2024 가중치는 각각 0.5·0.3·0.2를 유지하고 누락 연도의 가중치를 다른 연도로 옮기지 않는다.
- 성적·지원 전형을 변경하면 기존 진단 결과를 무효화한다.
- 5등급제와 9등급제 비교의 근사 변환은 실제 동일 기준 입결과 구분하여 안내한다.
- 실제 원점수·평균이 없는 그래프는 가상 숫자로 채우지 않는다.
- 진단 위치를 실제 합격 확률이나 합격 보장으로 표현하지 않는다.

향후 확정 보고서는 당시 입력, 입결 버전, 판단 기준 버전, 작성자·검토자·확정 시점을 함께 보존한다. 현재 브라우저 진단 결과 보존을 서버의 확정 보고서 이력 체계와 동일하게 보지 않는다.

## 9. API 활용 방향과 현재 적용 범위

| 대상 | 현재 상태 | 참고용 방향 |
|---|---|---|
| 대학어디가 | 외부 개발자용 공식 연동 명세 미확보, 실제 연동 미구현 | 명세·제공 범위·이용 조건을 확보한 뒤 검토. 현재는 검증된 파일 반영 우선 |
| 대학 공식 자료 | 출처 확인 대상 | 모집요강·변경 공지를 학년도·원문 기준으로 확인 |
| AI | PDF 추출·솔루션 생성 코드 존재. 외부 실호출 검증은 별도 | 자료 추출·요약·초안에 제한하고 수치 판단은 규칙으로 계산 |
| 주요 탐구 추천 | 과목·키워드 기반 템플릿 추천 | 외부 API를 필수로 두지 않고 실제 활동·원문·담당자 검토를 우선 |
| 도서·알라딘 | 검색 링크만 존재, 도서 서지 API 미연동 | 알라딘 OpenAPI는 공식 안내상 2026-10-30 종료. 실제 이용 가능한 제휴·대체 수단을 확인한 뒤 별도 결정 |
| 메일·결제 | 관련 코드 존재 | 발신·결제 설정과 실제 거래 검증을 별도 수행 |

도서·논문·자료 추천 문구가 표시된다는 이유만으로 해당 책이나 논문의 실제 존재·저자·ISBN·원문을 검증했다고 보지 않는다. 실재 도서 검색과 서지 확인을 붙이기 전에는 담당자의 확인이 필요하다. 알라딘 연동을 완료한 것으로 표시하지 않는다.

API를 추가하기 전에는 필요한 데이터, 제공 조건, 사용 범위, 갱신 주기, 비용·응답시간·장애 시 동작을 확인한다. 학생 정보와 원문을 외부 서비스로 보내는 범위도 구분한다. API 키는 공개 코드·엑셀·문서에 기록하지 않는다.

알라딘 종료 안내 확인 출처: [알라딘 고객센터 공지](https://www.aladin.co.kr/cs_center/wcs_main.aspx?start=we)

## 10. 저장·운영 구조

GitHub → Vercel의 앱·서버 처리 → PocketBase 영구 저장소를 기준으로 한다.

공통 입결은 본사 공통 근거로 버전 관리한다. 학원별 학생 원문·상담·보고서는 조직·학생·담당자와 연결하여 접근을 제한한다. 현재 공통 입결 저장 모듈과 달리 프로필·주문·이용권·사용량에는 기존 로컬 파일 저장 경로가 남아 있다. 다학원 운영에 앞서 영구 저장·동시 수정·백업·복구를 통합해야 한다.

현재 관리자 조회는 서버의 관리자 이메일 목록을 기준으로 한다. 배포 후 비로그인 관리자 API 요청은 401로 거부되는 것을 확인했다. 이는 학원별·담당자별 전체 접근 분리가 구현되었다는 의미는 아니다.

## 12. 폴더·파일 정리 결과

로컬 프로젝트 폴더명은 **수프리마랩**으로 유지한다. 기존 GitHub 저장소명과 Vercel 프로젝트명·운영 도메인은 연결 유지를 위해 변경하지 않았다.

| 위치 | 용도 |
|---|---|
| app | 화면과 서버 처리 |
| lib / src/lib | 진단·인증·저장 등 공통 기능 |
| data / config | 입시 자료와 설정 |
| public | 서비스에서 사용하는 이미지·로고 |
| scripts | 자료 처리·회귀 검증·운영 도구 |
| docs | 기획·구조·기술·검증·배포 문서 |
| fly | PocketBase 배포 참고자료 |
| 화면구성_플로우별 | 이용 흐름별 전체 화면, 모바일 캡처, 개선 시안 |
| outputs | 로컬 검증·운영 화면 확인 결과. Git·배포 제외 |
| .cache | 로컬 운영 정보. 삭제하지 않고 Git·배포 제외 |

기존 정리에서는 불필요한 중간·임시 파일 24개를 제거하고 사전 백업을 보관했다. 이번 배포 정리에서는 과거 캡처 12개를 화면 검토 폴더로 옮겨 해시를 확인했고, 동일 보관본이 있는 중복 캡처만 제거했다. 자료 처리에 쓰이는 원본·최신 도구·수치 근거는 임의 삭제하지 않았다. node_modules와 빌드 결과는 로컬 재실행 편의를 위해 유지했다.

화면 검토자료·로컬 운영 정보·개발 도구는 배포 대상에서 제외한다. 원본 입결 엑셀은 바탕화면 수시 폴더에 별도 보존한다.
